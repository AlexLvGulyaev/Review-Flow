# ❓ Review Flow — ответы на частые вопросы

**Проект:** review-flow  
**Дата:** 2026-08-09

---

## 🧩 1. Общие вопросы

### 1.1. Что такое Review Flow?

Review Flow — демонстрационный MVP системы обработки клиентских обращений по архитектуре **Controlled Hybrid**. Клиент отправляет обращение, оператор проверяет и публикует ответ, администратор развивает базу знаний через типовые ситуации и кандидатов.

---

### 1.2. Какие роли есть в системе?

| Роль | Что делает | Точка входа |
|---|---|---|
| **Клиент** | Отправляет обращение и проверяет статус | Главная страница `/` |
| **Оператор** | Проверяет обращения, выбирает/подтверждает ТС, публикует ответ | `/company` |
| **Администратор** | Управляет ТС, кандидатами, промптами, настройками | `/company` → меню администратора |
| **Руководитель / аналитик** | Смотрит отчёты | `/reports` |

## 🧠 2. Controlled Hybrid

### 2.1. Почему LLM не выбирает типовую ситуацию?

Это **задуманное ограничение** Controlled Hybrid. Типовую ситуацию подбирает **retrieval** по примерам в базе; LLM только **перефразирует** утверждённый ответ в рамках policy. Так бизнес контролирует решения и аудит.

---

### 2.2. Что такое confidence?

**Уверенность** — насколько хорошо score retrieval отделил лучшую типовую ситуацию от остальных. Отображается как **Высокая / Средняя / Низкая**. Низкая уверенность — сигнал оператору внимательнее проверить выбор и альтернативы.

---

### 2.3. Что такое типовая ситуация (Response Case)?

**Response Case** — управляемый артефакт базы знаний, который фиксирует:

- атрибуты случая (сценарий, тональность, приоритет, направление, тема);
- `response_policy` — правила и ограничения ответа;
- `approved_response_text` — утверждённую основу текста;
- порог уверенности;
- retrieval-примеры обращений.

---

### 2.4. Что такое кандидат?

**Кандидат** — заявка на изменение базы знаний: новая типовая ситуация или новый retrieval‑пример. Оператор инициирует (часто через эскалацию), **администратор** принимает решение: создать ТС, объединить с существующей или отклонить.

---

### 2.5. Почему клиент не видит внутренние статусы?

Клиентский портал показывает только **понятные этапы** («обрабатываем», «на проверке», «опубликован ответ»). Номера типовых ситуаций, confidence и кандидаты — внутренние данные контура компании.

## ✏️ 3. Операторский контур

### 3.1. Что делать, если система ошиблась с типовой ситуацией?

1. Выберите правильную ТС в **альтернативах** (кнопка **«Выбрать»**).
2. Или нажмите **«Эскалация ТС»** с причиной «корректировка» / «ни одна не подходит».
3. Отредактируйте текст в **«Ответ оператора»** перед **«Одобрить и отправить»**.

---

### 3.2. Когда нужно эскалировать?

Эскалируйте, если:

- предложенная типовая ситуация не подходит;
- альтернативы тоже не покрывают кейс;
- текст LLM-черновика явно нарушает policy;
- ситуация требует нового бизнес-решения, которого нет в KB.

---

### 3.3. Можно ли опубликовать ответ без выбора ТС?

Да — после эскалации «ни одна ТС не подходит» поле **«Ответ оператора»** разблокируется, и оператор может написать ответ вручную. Но лучшее решение для повторяющихся кейсов — создание новой ТС из кандидата.

---

## 🎛️ 4. Административный контур

### 4.1. Как добавить новую типовую ситуацию?

1. Перейдите в **«Типовые ситуации»**.
2. Нажмите **«Добавить»**.
3. Заполните код, название, policy, approved response, НСИ-атрибуты.
4. Добавьте retrieval-примеры.
5. Сохраните и активируйте.

---

### 4.2. Как обработать кандидата от оператора?

1. Откройте вкладку **«Кандидаты»** в разделе типовых ситуаций.
2. Выберите кандидата.
3. Принимайте одно из решений:
   - **Создать новую ТС**;
   - **Объединить** с существующей (текст обращения станет примером);
   - **Отклонить** с комментарием.

---

### 4.3. Где настраивается AI-провайдер?

В меню **«Системные настройки»** → блок **AI-провайдеры**. Детальные настройки моделей — на странице `/settings/ai-providers`.

## 🚀 5. Развёртывание и demo

### 5.1. Как запустить Review Flow локально?

См. [`DEPLOYMENT_GUIDE.md`](DEPLOYMENT_GUIDE.md): скопируйте `.env.example` в `.env`, выполните `docker compose up --build`, откройте http://localhost:5180.

---

### 5.2. Где публичный demo?

| Контур | URL |
|---|---|
| Web UI клиента | https://review-flow.alex-n8n.site |
| Admin Console | https://review-flow-admin.alex-n8n.site/company |
| Backend API | https://review-flow-api.alex-n8n.site/docs |

---

### 5.3. Можно ли использовать Review Flow как production-решение?

Текущий репозиторий — **демонстрационный MVP**. Перед production нужно добавить: корпоративную аутентификацию, HTTPS/сертификаты, бэкапы БД, мониторинг, CI/CD, интеграцию с CRM/тикет-системой.
